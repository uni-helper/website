::alert{type="warning"}
`autoGenerate` 配置已废弃，配了不会有任何效果。

`unh` 检测到该配置时，会打印一条警告并提示删除：

```text
警告: 检测到已废弃的配置项 autoGenerate.pages，配置文件会在 dev/build 前自动生成，该项已无任何效果，可以从 unh.config.ts 中删除
```
::

## 现在的行为

`pages.json`、`manifest.json`、`uni-pages.d.ts` 在 `dev`、`build` 之前自动生成，不需要配置，也不需要手动创建或提交。

生成方式是：`unh` 在子进程里执行一次 vite 的 `resolveConfig`。这一步只触发插件初始化钩子，不进入打包阶段，让插件把真实内容写到磁盘，然后再执行 `uni` 命令。

## 前提条件

预生成只在项目安装了以下插件之一时执行：

- [@uni-helper/vite-plugin-uni-pages](/vite-plugin-uni-pages)：生成 `pages.json` 与 `uni-pages.d.ts`
- [@uni-helper/vite-plugin-uni-manifest](/vite-plugin-uni-manifest)：生成 `manifest.json`

生成失败只打印警告，不阻断命令。命令仍会继续，`uni` 读到的可能是占位内容。

## 迁移

从旧配置迁移时，删除整段 `autoGenerate`：

```ts [unh.config.ts]
import { defineConfig } from '@uni-helper/unh'

export default defineConfig({
  // 删除以下整段
  // autoGenerate: {
  //   outDir: 'src',
  //   pages: true,
  //   manifest: true,
  // },
})
```

插件装在项目里就够了，不需要其他操作。

## 为什么改了

类型定义里的说明是：配置由对应插件在 `dev`、`build` 前自动生成，`unh` 预先触发插件完成生成，保证配置内容真实有效。

因此不再需要 `outDir`、`pages`、`manifest` 这类选项来控制生成过程。
